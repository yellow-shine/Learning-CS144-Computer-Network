# CS144 整套参考实现与带读方案

## 1. 已确认的学习约定

- 学习者熟练使用 Go，接触过少量 C++，有 socket、抓包和网络排障经验，尚未开始 CS144。
- 主目标是深入理解协议实现，次目标是解释原理与设计取舍；第一阶段不宣称已具备独立实现能力。
- 每周投入 4–6 小时，无硬性截止日期。
- 先准备整套实现及验证记录，再开始带读；不是随学随写。
- 先用一个短单元串起应用、TCP、IP、链路层，再逐实验讲解。
- 中文讲解保留英文术语，C++ 随代码补充，Go 仅用于概念对照。
- 不要求独立编码、不安排强制测验，保留提问和讨论。
- 项目只在本地准备，不公开发布解答，不向课程平台提交作业。

## 4. 架构与实现约束

保留 minnow 原有结构和公开接口，不另造网络框架：

- `src/`：实现 ByteStream、Reassembler、Wrap32、TCPReceiver、TCPSender、
  NetworkInterface 和 Router；优先修改课程允许的文件。
- `apps/`：补齐课程要求的应用代码，复用 socket、TCP 和 end-to-end 应用。
- `util/`：复用现有序列化、报文解析、socket、事件循环和协议连接逻辑。
- `tests/`、`etc/`：保留原有测试与构建要求，不删测试、不放宽断言来制造通过。
- `writeups/`：记录每个 checkpoint 的设计、验证与限制。
- `docs/`：来源说明、运行方法、全景导读、C++/Go 对照和阅读顺序。
- `scripts/`：只在现有工具不能覆盖时添加最小测量、分析或复现脚本。

数据路径：应用字节 → 发送 ByteStream → TCPSender → TCP/IP 报文 →
NetworkInterface/ARP → Ethernet → Router → 对端网卡 → TCPReceiver →
Reassembler → 接收 ByteStream → 应用。具体封装与事件驱动由现有框架承担。

实现时逐模块读完公开接口、调用方和测试，再选择最简单满足容量与性能约束的数据结构。
关注容量不变量、重复/重叠处理、序列号回绕、ACK 合法性、EOF 与错误状态、重传时钟、
ARP 生命周期、无路由及 TTL 耗尽等边界；不省略输入校验和错误处理。
不额外实现生产级 TCP 功能、拥塞控制算法或通用可配置协议框架，除非固定版本实验要求。

## 5. 运行与验证

已检查宿主机为 macOS ARM64，安装了 Git、CMake、Ninja、Apple Clang；
`docker info` 返回可用的 Linux/aarch64 服务。尚未拉取课程运行镜像，也未运行实验构建。

采用 Ubuntu 24.04 Linux 容器，避免为 macOS 重写 Linux TUN/TAP 相关代码。
讲义要求支持 C++23 的工具链，并说明验收环境为 g++ 13.3；
固定代码的 `etc/cflags.cmake` 实际设置 C++20。保留项目现有编译标准，
使用支持它的 Ubuntu 24.04 工具链，并在验证记录中写出实际编译器版本。

- 复用 CMake/CTest、ASan/UBSan 与官方 `check0`、`check1`、`check2`、
  `check3`、`check5`、`check6`、`speed` 目标。
- 默认 `test` 目标排除了 webget 和速度测试；因此它通过不代表全部验证通过。
  HTTP 与性能检查必须另行执行和记录。
- 每个非平凡新增辅助程序留下至少一个可运行检查，优先使用标准库，不引入新测试框架。
- 记录测试命令、日期、工具链、结果和失败原因；不只记录“通过”。
- 容器权限采用最小范围。TUN/TAP 检查若需要 `NET_ADMIN` 和 `/dev/net/tun`，

- 外部网络、校内身份、同伴和长期观测不是可假定具备的前置条件。

## 6. Git 与交付顺序

比较过三种安排：每课一个长期分支方便切换但维护多；无阶段记录最简单但不利于带读；
采用 **一个主线 + 阶段提交/标签**，既能保留完整实现，又能按 diff 阅读。

1. 初始化本地 Git 仓库，提交本方案。
2. 导入固定 revision 的原始起始代码，保留出处，打 `starter-2025` 标签。
3. 按依赖顺序实现各 checkpoint，分别提交，并在对应检查完成后加 `checkpoint-N` 标签。
4. 汇总验证记录和中文导读；整体复查后才将参考实现标记为可带读。
5. 只有确需隔离实验性改动时才建临时分支，不建立八条长期维护分支。

不配置解答发布远端，不 push。构建输出、临时测量原始数据和个人网络信息不默认提交。

## 7. 带读方式

整套准备完成后，先讲一个短全景单元，再按课程顺序带读。
每个模块采用：问题 → 具体例子 → 最小模型 → 状态和不变量 → 关键执行路径 →
边界情况与实际测试结果。讲清语义而非逐行念代码。
不预先给每节课硬性时长，不用强制练习检验进度；根据提问调整解释深度。
